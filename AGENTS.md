authoritative file for each topic and deliberately does not restate it. If something here disagrees with
the file it points to, the other file wins.

## Layout

The authoritative map is the **Layout** section of [`README.md`](README.md), and the per-file writer table
is in [`config/README.md`](config/README.md). The two directories an agent changes most:

```
script/
  deploy/        BootstrapFactory, DeployResolver, DeployVerifier
  configure/     one script per privileged call, one chain at a time
  config/        sync-ccip-config.sh — Chainlink's chain reference, synced from the CCIP API
  ownership/     per-target two-step transfers (owner + storageLocationsAdmin)
  governance/    ValidateConfig, SnapshotOperator, DriftCheck, LaneParityCheck, deployments-report
src/lib/         ConfigLib, BaseScript (EOA/Safe switch), Types — the glue the scripts share
config/          config-as-data: chains/ (synced), operator*/ (yours), deployments/ (script-written)
```

## Generated files: never edit these by hand

- **`docs/src/deployments.md`** is produced by
  [`script/governance/deployments-report.sh`](script/governance/deployments-report.sh) from `config/`
  (`make deployments-doc`). Edit the generator or the config, not the page; `make deployments-check`
  reports when it is stale.
- **`config/deployments/*.json`** is written by the deploy scripts (`forge` `writeJson` form). Hand-editing
  it fights the next deploy and breaks the canonical shape.
- **`config/chains/*.json`** is written by `script/config/sync-ccip-config.sh` from the CCIP API. A `sync`
  overwrites hand edits; change it upstream or accept drift, never by hand.
- **`make help`** is generated by grepping the `##` comments in the `Makefile`; a target's description
  lives in its `##` line, not in a separate list.

## Invariants when changing the kit

These are the rules that are not discoverable by reading the tree, in rough order of how often they are
broken.

**Address determinism lives in the `default` profile — never deploy anything address-sensitive from `dev`.**
[`foundry.toml`](foundry.toml) pins solc, optimizer, `evm_version`, and `bytecode_hash` to match
`@chainlink/contracts-ccip@2.0.0` so the `CREATE2Factory` and `VersionedVerifierResolver` land at the same
address on every chain. The `dev` profile compiles different bytecode and different addresses. Every deploy
target in the `Makefile` hard-pins `FOUNDRY_PROFILE=default` inline for this reason — do not remove it. Do
not add a compiler override to the `ci` profile either: it inherits `default` on purpose so CI validates the
bytecode you actually ship, and only adds `deny = "warnings"`.

**`config/` is config-as-data with exactly one writer per file.** See the writer table in
[`config/README.md`](config/README.md): `chains/` is synced from the CCIP API, `operator.json` + `operator/`
are the operator's, `deployments/` is written by the deploy scripts. The `ConfigLib` loader rejects any key
outside a file's documented set, so adding a field is not a one-line change: add it to the loader in
[`src/lib/ConfigLib.sol`](src/lib/ConfigLib.sol), to the matching `_template.json`, and to
[Config file schema](docs/src/config-schema.md), or the file stops loading.

**Every `configure` / `ownership` / `fee` run needs `OUTPUT_MODE`, and it has no default.** `EOA` broadcasts
live transactions; `SAFE` writes an `out/safe/` batch and broadcasts nothing. The `Makefile` refuses to
guess because `EOA` moves real funds and roles, so selecting it is an explicit opt-in. The scripts read the
same env var through [`src/lib/BaseScript.sol`](src/lib/BaseScript.sol); keep the two in step.

**`forge` is pinned to `1.8.1` in both the `Makefile` (`FOUNDRY_VERSION`) and CI
([`ci.yml`](.github/workflows/ci.yml)).** `fmt` and `lint` output changes between releases, and
`foundry.toml`'s `[lint] exclude_lints` names ids that older releases reject as "unknown id", so a version
drift turns the gate red with no code change. Bump both together.

**Tests are hermetic — keep them that way.** `make test` runs `forge test` with no RPC and seeds
`config/operator.json` from the example first (`seed-operator-config`, copy-if-absent, the same target CI
uses). A test that reaches the network, or that leaves a real-named file under `config/`, breaks the
fresh-clone guarantee. Every filesystem test writes its **own** unique path under a scratch dir (for example
`out/governance/`) and never touches `config/deployments/`; the trailing `vm.removeFile` is courtesy, since
a failed assertion reverts before it, so correctness must not depend on it.

**Adding a `Makefile` target means adding its `##` help line** — a target without one is invisible to
`make help` and to the Start-here table above.

## Releases

Pushing a **`v`-prefixed tag** to `main` triggers [`release.yml`](.github/workflows/release.yml), which
drafts a GitHub release with auto-generated notes from the merged PRs. Add
`changelogs/<version>.md` before tagging only if you want curated prose on top; see
[`changelogs/README.md`](changelogs/README.md). The draft waits for a maintainer before it goes public.

## Known gaps

Stated so an agent does not assume coverage that is not there.

- **The shell wrappers under `script/` have no unit tests.** `shellcheck --severity=warning` and the offline
  `script/config/selftest.sh` are their only gates in CI.
- **`make deployments-check` is not wired into CI.** A stale `docs/src/deployments.md` will not fail a build
  unless you run the check yourself, so regenerate the page (`make deployments-doc`) as part of any change
  that adds or moves a deployment.
